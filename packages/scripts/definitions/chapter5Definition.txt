CHAPTER 5: Fuel Token Crowdsale Contract Audit Requirements

This chapter requires a fuel token crowdsale system that raises 50,000 credits to upgrade a station.

=== REQUIRED FUNCTIONS ===

1. buy(uint256 amount) - Purchase fuel tokens with credits
   ✅ MUST: Be external/public
   ✅ MUST: Calculate cost as: (amount * pricePerToken) / 10**18
   ✅ MUST: Transfer credits from caller: creditsContract.transferFrom(msg.sender, address(this), cost)
   ✅ MUST: Mint/transfer tokens to caller
   ✅ MUST: Revert if upgraded == true

2. pricePerTokenInCredits() returns (uint256) - Get token price
   ✅ MUST: Be public/external view/pure
   ✅ MUST: Return uint256 price

3. balanceOf(address) returns (uint256) - ERC-20 balance check
   ✅ MUST: Return token balance for address

4. redeem() - Burn token for refueling service
   ✅ MUST: Take NO parameters
   ✅ MUST: Burn exactly 1 * 10**18 tokens from msg.sender

5. upgrade() - Trigger station upgrade
   ✅ MUST: Take NO parameters
   ✅ MUST: Check contract has >= 50,000 * 10**18 credits
   ✅ MUST: Set upgraded = true BEFORE any external calls
   ✅ MUST: Approve Game for EXACTLY 49,500 * 10**18 credits
   ✅ MUST: Call game.upgradeStation(sectorId)
   ✅ MUST: Transfer >= 500 * 10**18 credits to msg.sender (the pilot caller)

=== CEI PATTERN VERIFICATION ===

To verify CEI pattern in upgrade() function, follow these steps:

STEP 1: Find the line where "upgraded = true" is set
STEP 2: Find ALL lines with external calls (approve, transfer, upgradeStation, etc.)
STEP 3: Verify "upgraded = true" comes BEFORE all external calls

Example CORRECT pattern:
```solidity
upgraded = true;                                              // Line N (state change)
creditsContract.approve(gameAddress, 49500 * 10**18);        // Line N+2 (external call)
game.upgradeStation(sectorId);                                // Line N+4 (external call)
creditsContract.transfer(msg.sender, 500 * 10**18);          // Line N+6 (external call)
```

If you see "upgraded = true" appearing BEFORE all external function calls in the code, the CEI pattern is CORRECT.

=== PASS CONDITIONS ===

✅ All 5 required functions present with correct signatures
✅ buy() calculates cost correctly and transfers credits + mints tokens
✅ buy() reverts when upgraded == true
✅ redeem() burns exactly 1 token, takes no parameters
✅ upgrade() follows CEI pattern (upgraded = true BEFORE external calls)
✅ upgrade() checks >= 50k credits, approves exactly 49.5k, calls upgradeStation, rewards caller >= 500
✅ Proper ERC-20 implementation
✅ No security vulnerabilities

=== FAIL CONDITIONS ===

❌ Missing any required function
❌ Wrong function signatures (wrong names, extra/missing parameters)
❌ buy() missing division by 10**18 in cost calculation
❌ buy() doesn't revert when upgraded == true  
❌ redeem() takes parameters or doesn't burn exactly 1 token
❌ upgrade() sets upgraded=true AFTER external calls (CEI violation)
❌ upgrade() doesn't approve exactly 49,500 * 10**18
❌ upgrade() doesn't call upgradeStation
❌ upgrade() rewards caller < 500 * 10**18
❌ Security vulnerabilities or rug mechanisms

=== NOTES ===

- msg.sender in upgrade() IS the pilot caller - rewarding msg.sender is correct
- Contract may have > 50k credits when upgrade() is called (excess is fine)
- Order of operations AFTER state change doesn't matter (approve/upgradeStation/transfer can be in any order)
- game.upgradeStation() synchronously pulls 49,500 credits during the call
- Either single contract or separate token+crowdsale contract is acceptable
